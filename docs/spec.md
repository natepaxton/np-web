# np-aspire — Project Spec

Status: early draft. Sections marked **TBD** are open decisions.

This repository is the **Angular frontend** of np-aspire: an Nx monorepo of Angular apps and libraries. The backend lives in **[np-aspire-api](https://github.com/natepaxton/np-aspire-api)**: the .NET API, the Aspire AppHost, the NGINX gateway, the Docker Compose stack (`compose.yaml`), and the Auth0 configuration (Terraform and the permissions manifest). Its `docs/spec.md` covers those parts.

Until 2026-09-17 both lived here. The combined state is tagged **`pre-api-split`**. The .NET history was moved to np-aspire-api with `git filter-repo`.

## 1. Goal

An Nx monorepo for Angular apps and shared libraries. The apps talk to the np-aspire-api backend through its NGINX gateway, and they ship as a static-site container image that the backend's `compose.yaml` runs behind the gateway.

## 2. How the frontend fits the system

```
 Browser ──── login ────► Auth0
    │  HTTP (same origin) + Auth0 access token
    ▼
 NGINX gateway (np-aspire-api)
    ├── /      → web: this repo's static-site image
    └── /api/  → API (np-aspire-api)
```

- **All browser traffic goes through the gateway.** Apps call the backend with **relative URLs** (`/api/v1/...`) and never use hardcoded hosts or ports.
- **Same origin:** the frontend and the API share one origin, so no CORS setup is needed.
- **Local development:**
  - Run the backend with np-aspire-api, either as its Aspire AppHost or as its compose stack. The compose stack puts the gateway on `http://localhost:8080`.
  - Run `npx nx serve sandbox` here. The dev server's proxy config (`proxy.conf.json`, added in milestone 3) forwards `/api` to the backend.
  - Whether the proxy targets the gateway or the API directly depends on an open decision in np-aspire-api.
- **Containers:** each deployable app is built into a static-site image, served by NGINX with an SPA fallback, and published to GHCR (milestone 2). np-aspire-api's `compose.yaml` will add it as the `web` service, and the gateway's `/` will proxy to it.

## 3. Components

### 3.1 Projects

| Project       | Type           | Purpose                                                                                                                                                                                                 |
| ------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sandbox`     | app            | Developer test bed. It gets quick, minimal UI for exercising API endpoints as they are built. It is not production UI. Serves on port **4300**.                                                         |
| `sandbox-e2e` | Playwright e2e | End-to-end tests for `sandbox`.                                                                                                                                                                         |
| `ui`          | library        | Shared app-level components (composed from helm primitives), plus the shared theme and Tailwind entry styles. Import path `@np-aspire/ui`.                                                              |
| `helm-*`      | libraries      | spartan/ui **helm** components, generated by the Spartan CLI into `libs/helm/<name>`. This is our code to edit, and one Nx lib per primitive (project `helm-<name>`, import `@spartan-ng/helm/<name>`). |
| `auth`        | library        | Auth0 setup, the HTTP interceptor, and permission helpers (milestone 3).                                                                                                                                |

### 3.2 Standards

- Latest stable Angular, generated with the `@nx/angular` generators.
- Standalone components, signals, `OnPush` change detection, and built-in control flow (`@if`, `@for`).
- **UI library: spartan/ui** (MIT). It has two layers:
  - **brain:** headless, accessible primitives installed from npm as `@spartan-ng/brain`.
  - **helm:** Tailwind-styled components, copied into `libs/helm/`, that we own and edit.
  - **Style: Mira** (Spartan's compact design-system style), with **base color: neutral**. The style and the base color are separate settings.
  - The CLI reads `components.json` in the workspace root:
    ```json
    {
      "componentsPath": "libs/helm",
      "style": "mira",
      "importAlias": "@spartan-ng/helm",
      "generateAs": "library",
      "buildable": true
    }
    ```
    Keep this file committed, so every `nx g @spartan-ng/cli:ui` run uses the same style and location without prompting.
  - Add components with `npx nx g @spartan-ng/cli:ui <name>`.
  - Upgrade with the CLI's `migrate-*` and `healthcheck` generators.
  - Alternatives considered: Angular Material (rejected, to get a different look), PrimeNG (rejected: now a commercial license with a key-gated free tier), Taiga UI, NG-ZORRO, and the Angular CDK or Angular Aria with custom styling.
- **Styling: Tailwind CSS v4 + SCSS.**
  - Tailwind handles layout and utility styling in templates.
  - The Spartan theme (CSS variables) is the single source of truth for design tokens: colors, radius, and so on. Don't duplicate tokens as SCSS variables.
  - **SCSS stays the default for component styles** (set in the `nx.json` generator defaults).
  - Tailwind v4 must not go through Sass, so each app's **global** stylesheet is plain `styles.css`.
    - The shared entry is `libs/ui/src/styles/theme.css`. It holds the Tailwind layer imports, the Spartan preset, and the neutral theme variables. Tailwind's automatic source detection is turned off there (`source(none)`).
    - Each app's `styles.css` imports that file and declares `@source` paths for its own folder and for `libs/`.
    - PostCSS is configured once, in the root `.postcssrc.json`.
  - Component `.scss` files that need Tailwind's `@apply` must add `@reference` to the Tailwind entry. Prefer utility classes in templates over `@apply`.
- Unit tests use **Jest** (`jest-preset-angular`). Generate projects with `--unitTestRunner=jest`, because newer Angular and Nx versions may default to Vitest.
- Use Playwright for e2e tests. Each app gets its own `<app>-e2e` project.
- **Module boundaries** (ESLint, via project tags):
  - `type:app` may import `type:ui` and `type:helm`
  - `type:ui` may import `type:ui` and `type:helm`
  - `type:helm` may import `type:helm`
  - `type:e2e` may import nothing
  - Every project needs a tag.

### 3.3 Auth (Auth0, frontend side)

The API validates tokens and enforces all access rules (see np-aspire-api's spec §4–5). The frontend's part:

- **Login flow:** Authorization Code + PKCE through the Auth0 Angular SDK (`@auth0/auth0-angular`).
- **Audience:** the SPA requests tokens for the Auth0 **API** audience, so they are JWT access tokens.
- **Token storage:** tokens are kept in memory (the SDK default), with **refresh token rotation**. Never `localStorage`.
- **Interceptor:** the Auth0 HTTP interceptor's `allowedList` covers only `/api/*`, so tokens are never sent anywhere else.
- **Route guards** (`authGuard`) are for user experience only. They are not security.
- **Angular never decides access and never decodes access tokens.** It shows or hides UI based on the `permissions` returned by `GET /api/v1/users/me`.
- **Roles** (defined in np-aspire-api):
  - `member`: `read:profile`, `update:profile`. Auto-assigned on first login.
  - `admin`: adds `read:users`.
  - A user with no role gets 403 from the API.
- **Permission names are never hand-typed.** They come from the API contract (§3.4).
- **SPA settings** (callback, logout, and web-origin URLs, including `http://localhost:4300`) are managed by Terraform in np-aspire-api.

### 3.4 API contract

- np-aspire-api serves an OpenAPI document. It is the contract between the repositories.
- The frontend **generates** its API client and types from that document, including the permission names, which the API exposes as an enum. Hand-written API types are not used, because nothing else keeps the two repos in sync.
- Generator and document source: **TBD** (§6).

## 4. CI and repository settings

**GitHub Actions** (`.github/workflows/ci.yml`) runs on PRs into `main` and on pushes to `main`. A newer push cancels an in-progress run for the same branch.

- **`Lint, test, build` job:**
  1. `nx format:check`
  2. `nx affected -t lint build`
  3. `nx run-many -t test --configuration=ci`. All projects are tested so Codecov always gets a complete report. Revisit (affected tests plus Codecov carryforward flags) if test time grows.
  4. Coverage table written to the job summary (`tools/scripts/coverage-summary.mjs`).
  5. Upload to Codecov, and upload coverage reports as an artifact.
- **`E2E` job:** `nx affected -t e2e`, with Playwright browsers cached by version. The Playwright report is uploaded on failure.
- Shared job setup lives in `.github/actions/setup`: Node from `.tool-versions` (which asdf also uses locally), `npm ci`, and `nx-set-shas`.
- Nx Cloud is not used (`NX_NO_CLOUD=true`).
- **Later additions:**
  - build and push the static-site image (milestone 2)
  - an API-client drift check (milestone 3)

**Code coverage**

The test tools enforce the minimums, so CI and local runs fail the same way. Codecov adds reporting.

| Scope                                          | Lines / statements / functions | Branches |
| ---------------------------------------------- | ------------------------------ | -------- |
| Shared libraries (`ui`, …)                     | 80%                            | 75%      |
| `sandbox` (developer tool)                     | 60%                            | 50%      |
| Changed lines in a PR (Codecov `patch` status) | 80%                            | —        |

- Jest (Istanbul) enforces the minimums with `coverageThreshold` in each project's `jest.config.cts`.
- `collectCoverageFrom` lists all source files, so a file with no tests counts as uncovered.
- Reporters: `lcov` (for Codecov), `json-summary`, and `text-summary`.
- **Excluded from coverage:**
  - `libs/helm/**`
  - `main.ts`, `app.config.ts`, `*.routes.ts`, and `index.ts` barrels
  - generated `*.g.ts` files and generated API clients
- **Codecov (`codecov.yml`):**
  - `project` status: overall coverage may not drop by more than 1%.
  - `patch` status: changed lines must reach 80%.
  - One component per project.
  - Uploads use the `CODECOV_TOKEN` secret, stored as both an Actions secret and a Dependabot secret.
  - **Every new project with tests needs** a `collectCoverageFrom` and threshold in its Jest config, and a Codecov component.

**Branch protection on `main`** (public repository, applied with `gh api`):

- Changes go through a PR. No approvals are required, because this is a solo project; stale reviews are dismissed.
- Required checks: `Lint, test, build`, `E2E`, `codecov/patch`, and `codecov/project`.
- The branch must be up to date with `main` before merging.
- Review conversations must be resolved.
- No force pushes or deletions.
- The rules apply to admins too.

**Secret scanning:** secret scanning and push protection are enabled (free for public repositories). The optional non-provider patterns and validity checks require GitHub Secret Protection (paid), so they stay off.

**Dependabot**

- **Alerts and security updates:** enabled in the repository settings. Security fixes arrive as one grouped PR.
- **Version updates** (`.github/dependabot.yml`):
  - Checked every Monday at 06:00 America/New_York, with at most 5 open PRs per ecosystem.
  - New npm releases wait 3 days before being proposed (7 days for major releases).
  - Ecosystems: `npm` and `github-actions`. Add `docker` in milestone 2.
- **npm groups:** `nx`, `angular`, `ui-styling` (Spartan, Tailwind, PostCSS), and `minor-and-patch` for everything else. Other majors arrive as individual PRs.
- **Majors Dependabot ignores**, because they are upgraded with tooling that also migrates code:
  - Nx and Angular (`npx nx migrate latest`)
  - Spartan (the CLI's `migrate-*` generators)
  - `typescript` and `@types/node`, which follow Angular and Node
- **npm install-script approvals:**
  - `allowScripts` entries are name-only (`.npmrc`: `allow-scripts-pin=false`), so version bumps don't un-approve build tools.
  - A dependency that adds a _new_ install script still needs `npm approve-scripts <pkg>`.
  - Currently approved: `nx`, `esbuild`, `lmdb`, `@parcel/watcher`, `unrs-resolver`, and `msgpackr-extract`. `fsevents` is denied because its prebuilt binary is used.

## 5. Repository layout

```
apps/
  sandbox/                  Angular app (port 4300)
  sandbox-e2e/              Playwright tests
libs/
  ui/                       Shared app components, theme, Tailwind entry styles
  helm/                     spartan/ui helm components (generated, owned by us)
  auth/                     Auth0 setup and permission helpers (milestone 3)
tools/
  scripts/                  CI scripts (coverage summary)
docs/
  spec.md
.github/
  workflows/ci.yml          CI
  actions/setup/            Shared CI setup (Node, dependencies, Nx SHAs)
  dependabot.yml            Dependency updates
.tool-versions              Node version (asdf, CI)
.gitattributes              LF line endings
.postcssrc.json             Tailwind v4 PostCSS plugin
components.json             spartan/ui CLI config (style: mira)
codecov.yml
nx.json / package.json
```

This follows Nx conventions: deployable projects go in `apps/`, and shared libraries go in `libs/`.

## 6. Open decisions

- **API client generation:** the generator (for example `ng-openapi-gen` or `@hey-api/openapi-ts`), and where the OpenAPI document comes from: a copy committed and checked in CI, a release artifact from np-aspire-api, or a running API.
- **Static-site image:** name, tag scheme, and base image. It must be coordinated with np-aspire-api's `compose.yaml` and AppHost.
- **E2E credentials:** how the Playwright tests get the dev-tenant test-user passwords (GitHub secrets in this repo, matching np-aspire-api's Terraform variables).
