# np-aspire

Nx monorepo: Angular apps/libs + a single .NET API behind an NGINX gateway, orchestrated locally with Aspire, runnable as containers via docker-compose.

Full spec, architecture, and open decisions: @docs/spec.md

## Stack

- **Frontend:** Angular (latest stable) via `@nx/angular`, spartan/ui (brain + helm), Tailwind CSS v4, SCSS component styles, Jest unit tests, Playwright e2e
- **Backend:** one .NET 10 (LTS) ASP.NET Core API (controllers), PostgreSQL, EF Core + Dapper (Npgsql); `.csproj` projects join Nx via `@nx/dotnet`
- **Auth:** Auth0 (`@auth0/auth0-angular` in clients, JWT bearer validation in the API)
- **Gateway:** NGINX (`infra/nginx/`): `/` → Angular static files, `/api/` → API
- **Orchestration:** Aspire AppHost (dev + source of truth); docker-compose generated by `aspire publish` into `deploy/compose/`
- **Auth0 config:** Terraform (`infra/auth0/`, `auth0/auth0` provider), driven by `infra/auth0/permissions.json`
- **CI:** GitHub Actions (`.github/workflows/`)
- **Deferred:** microservices split, RabbitMQ (see spec §7)

## Layout

- `apps/` Angular apps (`sandbox`) and their `*-e2e` Playwright projects
- `libs/ui` shared app components, Spartan theme, Tailwind entry styles (`@np-aspire/ui`)
- `libs/helm/<name>` spartan/ui helm components (Nx projects `helm-<name>`, import `@spartan-ng/helm/<name>`) — generated by the Spartan CLI, but ours to edit; kept in upstream (tab) formatting and excluded from Prettier
- `apps/api/src|tests` the .NET API (`NpAspire.Api`). .NET projects are created with `dotnet new` (`@nx/dotnet` has no project generators): deployables in `apps/`, class libraries in `libs/`
- `aspire/` AppHost and ServiceDefaults
- `infra/nginx/` NGINX config; `infra/auth0/` Terraform + permissions manifest (Nx project `auth0-config`)
- `deploy/compose/` generated compose output (do not edit)

## Commands

- Install: `npm install` (npm blocks unreviewed install scripts; approve known build tools with `npm approve-scripts <pkg>`, recorded under `allowScripts` in `package.json`)
- Serve sandbox: `npx nx serve sandbox` → http://localhost:4300 (4200 is avoided on purpose)
- Lint / test / build everything: `npx nx run-many -t lint test build`
- Affected only: `npx nx affected -t lint test build`
- E2E: `npx nx e2e sandbox-e2e` (first time: `npx playwright install`)
- Format: `npx nx format:write` / `npx nx format:check`
- Test with coverage (as CI does): `npx nx run-many -t test --configuration=ci`
- Project graph: `npx nx graph`
- New Angular lib: `npx nx g @nx/angular:library libs/<name> --importPath=@np-aspire/<name>` (defaults for scss/jest/eslint live in `nx.json`), then add a `type:*` tag
- New component: `npx nx g @nx/angular:component <path>/<name>/<name>`
- New helm primitive: `npx nx g @spartan-ng/cli:ui <name>`, then rename its project to `helm-<name>`, tag it `type:helm`, and run `npx nx lint helm-<name> --fix`
- Run everything (dev): `dotnet run --project aspire/AppHost` (or `aspire run`)
- Generate compose: `aspire publish -o deploy/compose`
- Full stack in containers: `docker compose -f deploy/compose/docker-compose.yaml up`
- .NET build/test: `dotnet build` / `dotnet test`
- Regenerate permission constants: `npx nx run auth0-config:generate-permissions`
- Auth0 (dev tenant): `npx nx run auth0-config:tf-plan` / `tf-apply` (reads `AUTH0_DOMAIN`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, `TF_VAR_*` from gitignored `infra/auth0/.env.local`; template in `.env.example`)

## Rules

- Use Nx generators (`npx nx g ...`) to create Angular apps/libs/components; don't hand-roll project config.
- Angular projects use Jest: pass `--unitTestRunner=jest` to generators.
- Angular: standalone components, signals, `OnPush`, built-in control flow. No NgModules for new code.
- Module boundaries (ESLint, via project tags): `type:app` → `type:ui`, `type:helm`; `type:ui` → `type:ui`, `type:helm`; `type:helm` → `type:helm`; `type:e2e` → nothing. Every new project needs a tag.
- Shared UI goes in `libs/ui`, not duplicated across apps. Build it from helm primitives; add primitives with `npx nx g @spartan-ng/cli:ui <name>` (style `mira` and location `libs/helm` come from `components.json`; don't override them).
- Styling: Tailwind utilities in templates; component styles are SCSS. Global app stylesheets are plain `styles.css` (Tailwind v4 can't go through Sass) that import `libs/ui/src/styles/theme.css` and declare `@source` paths (automatic source detection is off). Design tokens are the Spartan theme CSS variables — don't duplicate them as SCSS variables. Prefer utilities over `@apply`.
- `sandbox` is a dev test bed. Keep its UI minimal and functional.
- Clients call the backend only through NGINX using relative URLs (`/api/v1/...`). Never hardcode hosts/ports in Angular.
- API routes are `api/v{version}/<plural-resource>` via `Asp.Versioning.Mvc`; controllers are plural (`UsersController`). NGINX forwards `/api/` paths unchanged and knows nothing about versions.
- EF Core for writes and migrations, Dapper for read-heavy queries.
- The API validates Auth0 JWTs itself; NGINX only forwards the `Authorization` header. Auth0 owns login/tokens — don't build login endpoints in the API.
- API is deny-by-default (fallback policy requires auth); opt out explicitly with `[AllowAnonymous]`.
- Authorization: Auth0 RBAC supplies `permissions` (`<action>:<resource>`) in the access token; the API checks permissions via named policies, never role names. Record-level rules (ownership etc.) live in the API.
- Permissions/roles are defined only in `infra/auth0/permissions.json`. Never hand-type permission strings; use the generated `Permissions.g.cs` / `permissions.g.ts` (regenerate with `npx nx run auth0-config:generate-permissions`, never edit `*.g.*` files).
- Roles: `member` (default, auto-assigned on first login) and `admin` (includes all `member` permissions — Auth0 roles don't inherit). A user with no role gets 403.
- Auth0 changes go through Terraform, not the dashboard (only exception: promoting real users to `admin`). Never commit `*.tfstate*`, `.terraform/`, or secret tfvars; do commit `.terraform.lock.hcl`.
- Angular never decides access and never decodes access tokens; it hides/shows UI based on `permissions` returned by `/users/me`.
- Identify the caller only from the token `sub` claim. A user's own data is accessed via `/users/me`, never by a client-supplied id.
- Auth0 is the identity source of truth; the local `Users` table stores only app-specific data keyed by `Auth0UserId` (`sub`).
- Never commit secrets (Auth0 config, DB passwords). Use Aspire parameters/user-secrets in dev, `.env` for compose.
- NuGet versions go in `Directory.Packages.props` (central package management).
- The AppHost is the source of truth for topology. Never hand-edit `deploy/compose/`; change the AppHost and re-publish.
- Let `@nx/dotnet` infer .NET targets; only add `nx:run-commands` targets for things it can't infer.
- Coverage minimums are enforced by the test tools: Jest `coverageThreshold` (libs 80/80/80/75, `sandbox` 60/60/60/50 for lines/statements/functions/branches), Coverlet for .NET. Never lower a threshold to make CI pass — add tests. New projects with tests need `collectCoverageFrom` + `coverageThreshold` in their Jest config and a component in `codecov.yml`.
- CI lives in `.github/workflows/ci.yml`; keep job names stable (`Lint, test, build`, `E2E`) because branch protection will reference them.
- When a TBD in `docs/spec.md` gets decided, update the spec.
