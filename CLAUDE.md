# np-aspire

Nx monorepo for the np-aspire **Angular frontend** (apps + shared libs). The backend — .NET API, Aspire AppHost (its only orchestration source), and Auth0/Terraform — lives in https://github.com/natepaxton/np-aspire-api (split on 2026-09-17; combined state tagged `pre-api-split`).

Full spec, architecture, and open decisions: @docs/spec.md

## Stack

- **Frontend:** Angular (latest stable) via `@nx/angular`, spartan/ui (brain + helm, Mira style, neutral theme), Tailwind CSS v4, SCSS component styles, Jest unit tests, Playwright e2e
- **Auth:** Auth0 via `@auth0/auth0-angular` (the API validates tokens and enforces access)
- **Backend contract:** the np-aspire-api OpenAPI document; the API client is generated from it (milestone 2)
- **Delivery:** production packaging/hosting is TBD (decided with np-aspire-api's deployment target); no gateway yet
- **CI:** GitHub Actions (`.github/workflows/`), Codecov

## Layout

- `apps/` Angular apps (`sandbox`) and their `*-e2e` Playwright projects
- `libs/ui` shared app components, Spartan theme, Tailwind entry styles (`@np-aspire/ui`)
- `libs/auth` Auth0 wiring — `provideNpAuth()` (`@np-aspire/auth`, tagged `type:ui`)
- `libs/helm/<name>` spartan/ui helm components (Nx projects `helm-<name>`, import `@spartan-ng/helm/<name>`) — generated by the Spartan CLI, but ours to edit; kept in upstream (tab) formatting and excluded from Prettier
- `tools/scripts/` CI scripts

## Commands

- Install: `npm install` (npm blocks unreviewed install scripts; approve known build tools with `npm approve-scripts <pkg>`, recorded name-only under `allowScripts` in `package.json`)
- Serve sandbox: `npx nx serve sandbox` → http://localhost:4300 (4200 is avoided on purpose)
- Backend for local dev (in np-aspire-api): `dotnet run --project src/NpAspire.AppHost` (API on http://localhost:5104)
- Lint / test / build everything: `npx nx run-many -t lint test build`
- Affected only: `npx nx affected -t lint test build`
- Test with coverage (as CI does): `npx nx run-many -t test --configuration=ci`
- E2E: `npx nx e2e sandbox-e2e` (first time: `npx playwright install`)
- E2E login tests: they need the API running and `E2E_TEST_USER_PASSWORD` in a gitignored root `.env.local` (same value as np-aspire-api's `TF_VAR_test_user_password`). Without either, they skip instead of failing.
- Format: `npx nx format:write` / `npx nx format:check`
- Project graph: `npx nx graph`
- New Angular lib: `npx nx g @nx/angular:library libs/<name> --importPath=@np-aspire/<name>` (defaults for scss/jest/eslint live in `nx.json`), then add a `type:*` tag
- New component: `npx nx g @nx/angular:component <path>/<name>/<name>`
- New helm primitive: `npx nx g @spartan-ng/cli:ui <name>`, then rename its project to `helm-<name>`, tag it `type:helm`, and run `npx nx lint helm-<name> --fix`

## Rules

- Use Nx generators (`npx nx g ...`) to create Angular apps/libs/components; don't hand-roll project config.
- Angular projects use Jest: pass `--unitTestRunner=jest` to generators.
- Angular: standalone components, signals, `OnPush`, built-in control flow. No NgModules for new code.
- Module boundaries (ESLint, via project tags): `type:app` → `type:ui`, `type:helm`; `type:ui` → `type:ui`, `type:helm`; `type:helm` → `type:helm`; `type:e2e` → nothing. Every new project needs a tag.
- Shared UI goes in `libs/ui`, not duplicated across apps. Build it from helm primitives; add primitives with `npx nx g @spartan-ng/cli:ui <name>` (style `mira` and location `libs/helm` come from `components.json`; don't override them).
- Styling: Tailwind utilities in templates; component styles are SCSS. Global app stylesheets are plain `styles.css` (Tailwind v4 can't go through Sass) that import `libs/ui/src/styles/theme.css` and declare `@source` paths (automatic source detection is off). Design tokens are the Spartan theme CSS variables — don't duplicate them as SCSS variables. Prefer utilities over `@apply`.
- `sandbox` is a dev test bed. Keep its UI minimal and functional.
- Call the backend only with relative URLs (`/api/v1/...`). Never hardcode hosts/ports; in dev the Angular proxy (`apps/sandbox/proxy.conf.mjs`) forwards `/api` to the API, defaulting to http://localhost:5104 and overridable with `API_URL` (the AppHost and Compose assign their own port). There is no gateway yet — relative URLs keep a future one transparent.
- Use the generated API client and types (from np-aspire-api's OpenAPI document); never hand-write API types or permission strings.
- Auth: Authorization Code + PKCE via `@auth0/auth0-angular`, wired up with `provideNpAuth()` from `@np-aspire/auth` — apps never call `provideAuth0()` directly. Tokens stay in memory (never `localStorage`) with refresh token rotation, for the `https://api.np-aspire.com` audience. `provideNpAuth({ apiBase })` derives the interceptor's `allowedList` from the API base; apps register `authHttpInterceptorFn` in their own `provideHttpClient`. Pass the same base the HTTP layer uses (`apps/sandbox/src/app/api.ts` holds the sandbox's) — if they disagree, no token is attached and every call fails as unauthenticated. The permission helpers land with the generated API client.
- The Auth0 tenant itself (SPA client, API, permissions, roles, test users) is Terraform in np-aspire-api `infra/auth0` — never the dashboard. Check it with `terraform -chdir=infra/auth0 plan -var-file=env/dev.tfvars` there before relying on a tenant setting here.
- Angular never decides access and never decodes access tokens; it hides/shows UI based on `permissions` returned by `GET /api/v1/users/me`. Route guards are UX only — the API enforces everything.
- Backend changes (endpoints, permissions, roles, Auth0 settings, orchestration) belong in np-aspire-api, not here.
- Coverage minimums are enforced by Jest `coverageThreshold` (libs 80/80/80/75, `sandbox` 60/60/60/50 for lines/statements/functions/branches). Never lower a threshold to make CI pass — add tests. New projects with tests need `collectCoverageFrom` + `coverageThreshold` in their Jest config and a component in `codecov.yml`.
- Upgrade Nx/Angular majors with `npx nx migrate latest` (then `npm install` and `npx nx migrate --run-migrations`), Spartan with its CLI `migrate-*` generators — never by hand-editing versions. Dependabot ignores those majors on purpose.
- Files use LF line endings (`.gitattributes`).
- `main` is protected: all changes go through a PR with passing CI (`Lint, test, build`, `E2E`, `codecov/patch`, `codecov/project`). Never push directly to `main`.
- CI lives in `.github/workflows/ci.yml`; keep job names stable (`Lint, test, build`, `E2E`) because branch protection references them.
- When a TBD in `docs/spec.md` gets decided, update the spec.

## Before Creating PRs

Run all CI checks locally before creating a pull request to catch issues early:

1. **Format**: `npx nx format:write` (or check with `npx nx format:check`)
2. **Lint**: `npx nx run-many -t lint` (or `npx nx affected -t lint` for changed projects)
3. **Test with coverage**: `npx nx run-many -t test --configuration=ci`
4. **Build**: `npx nx run-many -t build` (or `npx nx affected -t build` for changed projects)

If tests fail or coverage thresholds are not met, add or update tests. Aim for 100% coverage on new code — the `codecov/patch` check requires 80% on changed lines, but higher coverage catches more bugs and makes the codebase more maintainable.
